# نسخهٔ آزمایشی اشتراک‌گذاری شفاف فایل دانشگاه الزهرا

## رفتار برنامه
1. دانشجو مجوز رسمی دسترسی به فایل‌های مشترک اندروید را در تنظیمات فعال می‌کند. این مجوز به داده‌های خصوصی برنامه‌های دیگر دسترسی نمی‌دهد.
2. دانشجو نام، نام خانوادگی و رشته را وارد می‌کند. آدرس سرور در رابط دانشجو نمایش داده یا درخواست نمی‌شود؛ برنامه از مقدار ثابت زمان ساخت (`SERVER_BASE_URL`) استفاده می‌کند.
3. پیش از ثبت دستگاه، برنامه توضیح می‌دهد که مدیران مجاز می‌توانند فهرست فایل‌های مشترک قابل‌دسترسی را ببینند و فایل انتخاب‌شده را در زمان فعال بودن اشتراک‌گذاری دریافت کنند.
4. دستگاه تازه ثبت‌شده تا تأیید مدیر در داشبورد دسترسی انتقال ندارد.
5. هنگام اشتراک‌گذاری، اعلان دائمی اندروید نمایش داده می‌شود. دانشجو می‌تواند از برنامه یا اعلان اشتراک‌گذاری را متوقف کند.
6. مدیر فقط فایل‌هایی را می‌تواند درخواست کند که در آخرین فهرست ارسالی همان دستگاه وجود دارند. درخواست انتقال در داشبورد قابل لغو است.

## تنظیم آدرس ثابت برنامه
در GitHub مخزن، مسیر Settings → Secrets and variables → Actions → Variables را باز کنید و یک Repository variable با نام `SERVER_BASE_URL` و مقدار آدرس HTTPS نهایی مانند `https://api.example.com` بسازید. سپس GitHub Actions را دوباره اجرا کنید. اگر متغیر تنظیم نشده باشد، برنامه عمداً ثبت‌نام را انجام نمی‌دهد و پیام پیکربندی نشان می‌دهد.

## راه‌اندازی relay
- Node.js 20 یا جدیدتر لازم است.
- در پوشه `relay`: `npm install` و سپس `npm start`.
- متغیر محیطی `ADMIN_PASSWORD` را با رمز تصادفی حداقل ۲۰ کاراکتری تنظیم کنید.
- متغیر `PORT` در پلتفرم میزبانی از سوی میزبان تعیین می‌شود؛ برنامه آن را می‌خواند و روی `0.0.0.0` گوش می‌دهد.
- فقط از طریق HTTPS معتبر و دامنه ثابت منتشر کنید.
- برای حفظ اطلاعات پس از راه‌اندازی مجدد، پوشه `relay/data` باید روی دیسک پایدار/volume قرار گیرد. اگر میزبان فایل‌سیستم موقت دارد، حتماً volume پایدار متصل کنید.

## ملاحظات و محدودیت‌ها
- این نسخه نمونهٔ اولیه است و آزمون امنیتی مستقل، تست بار، تست بازیابی و تست روی مدل‌های مختلف اندروید را نگذرانده است؛ برای اطلاعات حساس یا استفاده واقعی دانشگاهی بدون بازبینی امنیتی استفاده نشود.
- اطلاعات دستگاه‌ها، فرمان‌ها و انتقال‌ها در `relay/data/state.json` نگهداری می‌شوند. فایل‌های دریافتی در `relay/data/uploads` هستند. این ذخیره‌سازی فایل‌محور برای نمونه اولیه است و جایگزین پایگاه‌داده عملیاتی/پشتیبان‌گیری نیست.
- فایل‌های انتقالی ممکن است حاوی اطلاعات شخصی باشند؛ دسترسی داشبورد را فقط به مدیران مجاز بدهید، رمز مدیر را در کد یا Git قرار ندهید و سیاست نگهداری/حذف فایل‌ها را مشخص کنید.
- مجوز گسترده اندروید شامل فایل‌های خصوصی برنامه‌های دیگر یا داده‌های محافظت‌شده نیست.
- اعلان دائمی باید برای اشتراک‌گذاری روشن باشد. دانشجو می‌تواند اشتراک‌گذاری را متوقف یا ثبت دستگاه را لغو کند.
- ثبت‌نام اولیه از سمت برنامه باز است، اما هر دستگاه تا تأیید مدیر در داشبورد اجازه فهرست‌گیری یا انتقال ندارد. برای استقرار عمومی، بهتر است ثبت‌نام با دعوت/کد یک‌بارمصرف سازمانی نیز محدود شود.
